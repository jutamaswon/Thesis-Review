# Thesis-Review (สกิลตรวจรีวิววิทยานิพนธ์ระดับดุษฎีบัณฑิต)

**Thesis-Review** คือสกิล (Skill) สำหรับ AI agent ที่รองรับระบบสกิล เช่น **ZCode** และ **Claude Code**
ใช้สำหรับ **ตรวจรีวิวเอกสารวิชาการ 2 ประเภท** คือ **วิทยานิพนธ์/ดุษฎีนิพนธ์** (โดยเฉพาะหลักสูตร DBA)
และ **บทความวิชาการเพื่อส่งตีพิมพ์ในวารสาร (journal manuscript)** ที่ส่งมาเป็นไฟล์ **PDF หรือ Word (.docx)**
ทั้งฉบับภาษาไทยและภาษาอังกฤษ โดยจำลองบทบาท **อาจารย์ที่ปรึกษา กรรมการตรวจระดับสูง
และผู้รีวิว (peer reviewer) ของวารสาร** ตรวจอย่างละเอียดระดับบรรทัด พร้อมอ้างอิงเลขหน้าของไฟล์ PDF ทุกประเด็น
แล้วสรุปเป็นรายงานรีวิวเชิงวิชาการ 2 รูปแบบ คือ **Markdown (.md)** และ **Word (.docx)**
ที่พร้อมส่งคณะกรรมการหรือใช้แก้ไขก่อน submit วารสาร

> หมายเหตุ: โปรเจกต์นี้เป็น "สกิล" ไม่ใช่โปรแกรมแบบสแตนด์อโลน — ต้องนำไปใช้ร่วมกับ AI agent
> ที่รองรับสกิล (ดูวิธีติดตั้งด้านล่าง) ไม่ต้องตั้งค่า API key ใด ๆ เพิ่มเติมภายในสกิล

## สิ่งที่สกิลนี้ทำได้

- **ตรวจจับประเภทเอกสารอัตโนมัติ** แล้วเลือกเกณฑ์การรีวิวที่เหมาะสม:
  - **วิทยานิพนธ์ (thesis)** — ตรวจพบโครงสร้างแบบมีบท (บทที่ 1, 2, …)
  - **บทความวิชาการเพื่อส่งวารสาร (manuscript แบบ IMRaD)** — โครงสร้างแบบ
    บทนำ → ทบทวนวรรณกรรม → ระเบียบวิธีวิจัย → ผลการศึกษา → อภิปรายผล → บทสรุป
- **ตรวจรับไฟล์** ทั้ง `.pdf` และ `.docx` (PDF ที่เป็นภาพสแกนจะใช้ OCR ได้)
- **แยกโครงสร้างเอกสารอัตโนมัติ** เป็นบทและหัวข้อย่อย รองรับหัวข้อภาษาไทยและอังกฤษ
  (`บทคัดย่อ`/`Abstract`, `บทที่ 1`–`บทที่ 5`, `เอกสารอ้างอิง`/`References` รวมถึงหัวข้อภายในบทความ `2.1`–`2.5`
  และหัวข้อ IMRaD ของ manuscript เช่น `1. Introduction`, `4. Results`)
- **ตรวจจับรูปแบบวิทยานิพนธ์ไทย 2 แบบโดยอัตโนมัติ** แล้วปรับเกณฑ์การรีวิวให้เหมาะสม:
  - **แบบ A — วิทยานิพนธ์โครงร่าง (Proposal-only):** มีเฉพาะบทที่ 1–3 (บทนำ การศึกษาเอกสาร ระเบียบวิธีวิจัย)
    จะรีวิวในฐานะโครงร่างก่อนเก็บข้อมูล โดยไม่ตำหนิที่ยังไม่มีผลการศึกษา แต่จะระบุว่าต้องส่งเพิ่มอะไร
  - **แบบ B — วิทยานิพนธ์แบบรวมบทความ (Multi-essay):** บทที่ 1 เป็นบทนำรวม (คำถามวิจัย วัตถุประสงค์
    ขอบเขต ประโยชน์ที่คาดว่าจะได้รับ เอกสารอ้างอิง) ตามด้วยบทความ (essay) 2–3 เรื่อง
    แต่ละเรื่องตรวจครบทั้ง 7 ส่วน: บทนำ → วรรณกรรม → ระเบียบวิธีวิจัย → ผลการศึกษา → อภิปราย →
    เอกสารอ้างอิง → ภาคผนวก และจะแจ้งเตือนหากบทความใดยังไม่ครบส่วน
- **สำหรับบทความวิชาการ (manuscript):** ตรวจครบตามมาตรฐานผู้รีวิววารสาร — ความใหม่/คุณูปการ
  ความรัดกุมของวิธีวิจัย การรายงานสถิติตาม APA คุณภาพตารางและภาพ ความทันสมัยของเอกสารอ้างอิง
  การเขียนแบบไม่เปิดเผยตัวตนสำหรับ double-blind review และปิดท้านด้วย
  **ข้อเสนอแนะในระดับผู้รีวิววารสาร (Accept / Minor revision / Major revision / Reject)
  พร้อมเหตุผลและรายการแก้ไขที่สำคัญที่สุด**
- **รีวิวละเอียดระดับบรรทัด 6 มิติ** ในทุกหัวข้อที่ตรวจ:
  1. วิชาการ/ระเบียบวิธีวิจัย (ทฤษฎี การออกแบบ การวิเคราะห์)
  2. เหตุผลและขั้นตอนการนำเสนอ (logical flow)
  3. ความถูกต้องของคำ (คำผิด ศัพท์เทคนิคคลาดเคลื่อน)
  4. การใช้ภาษาไทยที่ถูกต้องตามหลักราชบัณฑิตยสภา
  5. การเรียบเรียงคำ (ประโยคกำกวม ซ้ำซ้อน ยาวเกินไป)
  6. รูปแบบเอกสารและการอ้างอิง (APA การเรียงเลขหน้า ตาราง ภาพ)
- **ทุกประเด็นระบุหน้าของ PDF เสมอ** เช่น `(p. 47)` เพื่อให้ผู้เขียนตรวจสอบย้อนกลับได้
  (พร้อมตัวกรองปัญหา "ตัวอักษรไทยเพี้ยนจากการสกัดข้อความ PDF" ซึ่งไม่นับเป็นคำผิดของผู้เขียน)
- **สร้างรายงาน 8 ขั้นตอน** ตามลำดับมาตรฐาน: ภาพรวมโครงสร้าง → ชื่อเรื่อง → บทคัดย่อสองภาษา →
  บทนำรวม → รีวิวแต่ละบทความ → ตรวจเอกสารอ้างอิง
- **แนบตาราง Corrections Log** ท้ายรายงาน: รวมทุกข้อที่ต้องแก้ไขเป็นตาราง (ลำดับ | หน้า | หัวข้อ |
  ประเภท | ปัญหา | แนวทางแก้ไข | ระดับความร้ายแรง) เพื่อให้ผู้เขียนทำตามทีละข้อได้
- **ส่งมอบงาน 2 ไฟล์:** รายงาน `.md` สำหรับอ่าน และ `.docx` ระดับเอกสารทางการ
  (ฟอนต์ TH Sarabun New/Times New Roman, ตารางมีหัวคอลัมน์, เลขหน้า, จัดหน้าชิดขอบ)


## ข้อกำหนด (Requirements)

- AI agent ที่รองรับ "skill" ในรูปแบบโฟลเดอร์ที่มีไฟล์ `SKILL.md` เช่น **ZCode**, **Claude Code**
  (หากใช้ **ChatGPT** ซึ่งไม่มีระบบสกิลแบบโฟลเดอร์ ดูวิธีใช้แบบ "ชุดคำสั่ง + ไฟล์อ้างอิง"
  ในหัวข้อ [ใช้กับ ChatGPT](#ใช้กับ-chatgpt-เว็บ-chatgptcom) ด้านล่าง)
- **Python 3.8 ขึ้นไป** (สคริปต์ใช้เฉพาะไลบรารีมาตรฐาน ไม่ต้องติดตั้งแพ็กเกจเพิ่ม)
- แนะนำให้เลือกโมเดลระดับ **deep/reasoning** สำหรับการรีวิวเต็มรูปแบบ
  (เลือกโมเดลได้ในตัว AI agent เอง เช่น `/model` — สกิลนี้ไม่ต้องตั้งค่าคีย์ใด ๆ)

## วิธีติดตั้ง: นำ repository นี้ไปใส่ไว้ใน AI ของคุณ

หลักการง่าย ๆ: **คัดลอกทั้งโฟลเดอร์ repository นี้ไปวางไว้ใน "ไดเรกทอรีสกิล" ของ AI ที่คุณใช้**
(โฟลเดอร์ที่คัดลอกไปต้องมีไฟล์ `SKILL.md` อยู่ภายใน) แล้ว AI จะค้นพบและเรียกใช้สกิลนี้ได้เองโดยอัตโนมัติ

### ขั้นตอนที่ 1 — ดาวน์โหลด repository

```bash
git clone https://github.com/jutamaswon/Thesis-Review.git
```

หรือดาวน์โหลดเป็นไฟล์ ZIP จากหน้า GitHub (ปุ่ม **Code → Download ZIP**) แล้วแตกไฟล์

### ขั้นตอนที่ 2 — คัดลอกโฟลเดอร์ไปยังตำแหน่งที่ AI ค้นหาสกิล

เลือกตำแหน่งตามเครื่องมือที่คุณใช้ (ให้คัดลอก "ทั้งโฟลเดอร์" `Thesis-Review`):

| เครื่องมือ | ตำแหน่ง (ใช้กับทุกโปรเจกต์) | ตำแหน่ง (เฉพาะโปรเจกต์นั้น ๆ) |
|---|---|---|
| **ZCode** | `~/.zcode/skills/Thesis-Review/` | `<โปรเจกต์>/.zcode/skills/Thesis-Review/` |
| **Claude Code** | `~/.claude/skills/Thesis-Review/` | `<โปรเจกต์>/.claude/skills/Thesis-Review/` |
| **ใช้ร่วมหลายเครื่องมือ** (Claude / Codex / Cursor) | `~/.agents/skills/Thesis-Review/` | `<โปรเจกต์>/.agents/skills/Thesis-Review/` |

ตัวอย่างคำสั่ง (ZCode บน Windows):

```bash
git clone https://github.com/jutamaswon/Thesis-Review.git "$HOME/.zcode/skills/Thesis-Review"
```

ตัวอย่างคำสั่ง (Claude Code บน macOS/Linux):

```bash
git clone https://github.com/jutamaswon/Thesis-Review.git ~/.claude/skills/Thesis-Review
```

> เครื่องหมาย `~` หมายถึงโฟลเดอร์บ้านของผู้ใช้ เช่น บน Windows คือ `C:\Users\<ชื่อผู้ใช้>`
> เมื่อคัดลอกแล้ว ให้ตรวจสอบว่ามีไฟล์อยู่ครบตามพาธ เช่น `~/.zcode/skills/Thesis-Review/SKILL.md`

### ขั้นตอนที่ 3 — ตรวจสอบว่า AI พบสกิลแล้ว

เปิด AI agent ขึ้นใหม่ (restart) แล้วตรวจสอบ:

- **ZCode:** ดูที่ **Settings → Skills** หรือพิมพ์ `/` ในช่องคำสั่ง จะพบชื่อสกิล `academic-review`
- **Claude Code:** สกิลจะปรากฏในรายการสกิลของโปรเจกต์/ผู้ใช้โดยอัตโนมัติ

## ใช้กับ ChatGPT (เว็บ chatgpt.com)

ChatGPT ไม่มีระบบ "skill" แบบโฟลเดอร์ `SKILL.md` เหมือน ZCode หรือ Claude Code
แต่นำสกิลนี้ไปใช้ได้ในรูปแบบ **"ชุดคำสั่ง + ไฟล์อ้างอิง"** ผ่าน **Project** (ใช้ได้ทุกแพ็กเกจ)
หรือ **Custom GPT** (แพ็กเกจ Plus/Pro) ดังนี้:

1. **เตรียมไฟล์จาก repository นี้ 5 ไฟล์:**
   `SKILL.md`, `reference/rubric.md`, `reference/report-template.md`,
   `scripts/segment.py` และ `scripts/page_map.py`
   (กดที่ไฟล์ในหน้า GitHub แล้วเลือก **Download raw file** ทีละไฟล์ หรือ Download ZIP ทั้ง repo)

2. **สร้าง Project ใหม่** ใน ChatGPT (Sidebar → Projects → New project) ตั้งชื่อเช่น `Thesis Review`
   หรือหากมีแพ็กเกจ Plus/Pro สามารถสร้าง **Custom GPT** แทนได้

3. **อัปโหลดไฟล์ทั้ง 5** เข้าไปที่ **Project files** (หรือ **Knowledge** ของ Custom GPT)

4. **วางคำสั่งนี้** ในช่อง **Instructions** ของ Project (หรือ Custom GPT):

   ```text
   You are an elite academic reviewer (doctoral thesis advisor and journal
   peer reviewer). Follow the uploaded SKILL.md exactly: detect whether the
   document is a thesis or a journal manuscript, run the matching 8-step
   review in strict order, review every section across the six dimensions
   (Academic, Logical flow, Wording, Thai usage, Phrasing, Formatting/citation),
   cite the exact PDF page for every issue, and end with the Detailed
   Corrections Log appendix (for manuscripts, also the reviewer recommendation).
   Ask for the document file if none has been provided.
   ```

5. **แนบไฟล์วิทยานิพนธ์** (`.pdf` หรือ `.docx`) แล้วสั่ง เช่น
   `Review my thesis following SKILL.md`

6. **ขอรายงานผล:** ให้เขียนรายงานฉบับ Markdown ก่อน จากนั้นขอไฟล์ Word ต่อ
   (เช่น "สร้างไฟล์ .docx จากรายงานนี้ตามรูปแบบใน SKILL.md") — ChatGPT ใช้เครื่องมือ
   Python สร้างไฟล์ให้ดาวน์โหลดได้

### ข้อควรทราบเมื่อใช้กับ ChatGPT

- **วิทยานิพนธ์ยาวมากอาจอ่านไม่ครบในครั้งเดียว** — แนะนำแบ่งรีวิวทีละบท
  (สั่งต่อเนื่องหลายรอบใน Project เดียวกัน) แล้วขอให้รวมเป็นรายงานเดียวตอนจบ
- สคริปต์ `segment.py` และ `page_map.py` ให้ ChatGPT รันผ่านเครื่องมือวิเคราะห์ข้อมูล
  (Code Interpreter) ได้ โดยแนบไฟล์ข้อความของวิทยานิพนธ์ (`.txt`) ที่สกัดแล้วเข้าไปด้วย
- คุณภาพการรีวิวขึ้นกับโมเดลที่เลือก — แนะนำโมเดลที่เหมาะกับงานเอกสารยาว/ให้เหตุผลสูง
  และควรตรวจทานหมายเลขหน้าที่อ้างอิงกับไฟล์ต้นฉบับก่อนใช้งานจริง

## ใช้งานบนเดสก์ท็อป (ติดตั้งด้วยเมาส์ ไม่ต้องใช้ command line)

หากไม่ถนัดพิมพ์คำสั่ง สามารถติดตั้งสกิลนี้ด้วย File Explorer ล้วน ๆ ได้:

1. **ดาวน์โหลด:** ที่หน้า GitHub กดปุ่ม **Code → Download ZIP** แล้วแตกไฟล์
   (จะได้โฟลเดอร์ `Thesis-Review-main` — แนะนำเปลี่ยนชื่อเหลือ `Thesis-Review`)

2. **คัดลอกโฟลเดอร์** ไปวางที่ไดเรกทอรีสกิลของโปรแกรม (สร้างโฟลเดอร์ `skills` เองได้หากยังไม่มี):

   | ระบบ | ตำแหน่งที่วาง |
   |---|---|
   | Windows | `C:\Users\<ชื่อผู้ใช้>\.zcode\skills\Thesis-Review` |
   | macOS | `/Users/<ชื่อผู้ใช้>/.zcode/skills/Thesis-Review` (โฟลเดอร์ซ่อน — กด `Cmd+Shift+.` ใน Finder เพื่อแสดง) |

3. **ตรวจสอบ:** เปิดโปรแกรม **ZCode Desktop** ขึ้นใหม่ แล้วไปที่ **Settings → Skills**
   (หรือพิมพ์ `/` ในช่องคำสั่ง) จะต้องพบชื่อสกิล `dba-thesis-review`

4. **เริ่มใช้งาน:** สร้างโฟลเดอร์ทำงานสำหรับวิทยานิพนธ์แต่ละเรื่อง วางไฟล์ `.pdf`/`.docx`
   แล้วเปิดโฟลเดอร์นั้นในโปรแกรม แล้วสั่งรีวิวตามขั้นตอนพื้นฐานด้านล่าง

## วิธีใช้งาน (ขั้นตอนพื้นฐาน)

1. **เตรียมโฟลเดอร์ทำงาน** สำหรับวิทยานิพนธ์แต่ละเรื่อง แล้ววางไฟล์วิทยานิพนธ์ไว้ในโฟลเดอร์นั้น
   เช่น `my-thesis/thesis.pdf` (จะเป็น `.pdf` หรือ `.docx` ก็ได้)

2. **เปิด AI agent ในโฟลเดอร์ทำงานนั้น** (ใน ZCode หรือ Claude Code ให้เปิดโปรเจกต์/ไดเรกทอรีนี้)

3. **สั่งรีวิวด้วยข้อความธรรมดา** สกิลจะทำงานอัตโนมัติเมื่อคุณขอให้ตรวจเอกสารวิชาการ เช่น:

   - `"review my thesis at ./thesis.pdf"` (วิทยานิพนธ์)
   - `"review my dissertation"` (พร้อมชี้ไฟล์ในโปรเจกต์)
   - `"review my manuscript at ./paper.docx"` หรือ `"peer review this paper before journal submission"` (บทความวิชาการ)
   - `"ช่วยตรวจรีวิววิทยานิพนธ์ DBA นี้ให้หน่อย (ไฟล์ thesis.pdf)"`
   - `"ช่วยตรวจบทความนี้ก่อนส่งวารสาร (ไฟล์ manuscript.docx)"`
   - หรือชี้ไปที่ไฟล์ `.pdf`/`.docx` แล้วขอ feedback

   หากไม่ได้ระบุไฟล์ AI จะถามหาตำแหน่งไฟล์ก่อนเริ่ม
   สกิลจะตรวจจับเองว่าเป็นวิทยานิพนธ์หรือบทความวิชาการ แล้วเลือกเกณฑ์การรีวิวที่เหมาะสม

4. **รอกระบวนการทำงาน** — สกิลจะดึงข้อความ แยกบท/แยกหัวข้อ ตรวจจับประเภทและรูปแบบเอกสาร
   (วิทยานิพนธ์แบบ A หรือ B / บทความ IMRaD) แล้วรีวิวตามขั้นตอนทั้ง 8 ตามลำดับ
   เอกสารยาวอาจใช้เวลาสักครู่

5. **รับผลลัพธ์** — รายงานจะถูกบันทึกเป็น 2 ไฟล์ในโฟลเดอร์ `reviews/` ของโฟลเดอร์ทำงาน:

   ```
   reviews/<ชื่อวิทยานิพนธ์>-review.md     # รายงานฉบับอ่าน (Markdown)
   reviews/<ชื่อวิทยานิพนธ์>-review.docx    # รายงานฉบับทางการ (Word)
   ```

   ไฟล์งานระหว่างทางจะอยู่ในโฟลเดอร์ `_thesis_work/` (เก็บไว้ก็ได้ จะเอาไว้ใช้ตรวจซ้ำ)

## ขั้นตอนการรีวิวของสกิล (8 ขั้น ตามประเภทเอกสาร)

### วิทยานิพนธ์ (Thesis)

| ขั้น | เนื้อหาที่ตรวจ |
|---|---|
| 1 | ภาพรวมโครงสร้างเอกสาร + ระบุรูปแบบวิทยานิพนธ์ (A หรือ B) |
| 2 | ชื่อเรื่องวิชาการ (ความกะทัดรัด สอดคล้องเนื้อหา) |
| 3 | ความสอดคล้องของบทคัดย่อภาษาไทย–อังกฤษ |
| 4 | บทที่ 1 บทนำรวม (คำถามวิจัย วัตถุประสงค์ ขอบเขต ประโยชน์ เอกสารอ้างอิง) |
| 5–7 | แต่ละบทความ/บทวิจัย ครบทั้ง 7 ส่วน (บทนำ วรรณกรรม ระเบียบวิธี ผลศึกษา อภิปราย เอกสารอ้างอิง ภาคผนวก) |
| 8 | ตรวจสอบเอกสารอ้างอิงและการอ้างอิงในเนื้อหา (cross-check) |
| ท้ายเล่ม | ตาราง Detailed Corrections Log — รวมทุกข้อแก้ไขพร้อมเลขหน้าและระดับความร้ายแรง |

### บทความวิชาการ / Manuscript (IMRaD)

| ขั้น | เนื้อหาที่ตรวจ |
|---|---|
| 1 | ภาพรวมโครงสร้าง IMRaD + ตรวจความครบถ้วนของแต่ละส่วน (Present/Missing) |
| 2 | ชื่อเรื่อง คำสำคัญ (keywords) และข้อมูลหน้าแรก (พร้อมเสนอชื่อเรื่องทางเลือก) |
| 3 | บทคัดย่อ — ความครบถ้วนและสอดคล้องกับเนื้อหา (สองภาษาหากมี) |
| 4 | บทนำ — ความสำคัญของปัญหา ช่องว่างงานวิจัย คำถาม/วัตถุประสงค์ คุณูปการ |
| 5 | ทบทวนวรรณกรรม/กรอบทฤษฎี — ความครอบคลุม ความทันสมัย การสังเคราะห์ การกำหนดสมมติฐาน |
| 6 | ระเบียบวิธีวิจัย — การออกแบบ กลุ่มตัวอย่าง เครื่องมือ ความเที่ยง/ความตรง จริยธรรมวิจัย |
| 7 | ผลการศึกษาและอภิปราย — การรายงานสถิติตาม APA ตาราง/ภาพ การตีความ ข้อจำกัด |
| 8 | บทสรุป เอกสารอ้างอิง + **ข้อเสนอแนะระดับผู้รีวิววารสาร (Accept / Minor / Major / Reject)** |
| ท้ายรายงาน | ตาราง Detailed Corrections Log — รวมทุกข้อแก้ไขพร้อมเลขหน้าและระดับความร้ายแรง |

## ขอบเขตการใช้งาน

- **ใช้ได้กับ:** วิทยานิพนธ์ ดุษฎีนิพนธ์ (โครงร่างหรือฉบับสมบูรณ์)
  และ**บทความวิชาการเพื่อส่งตีพิมพ์ในวารสาร (journal manuscript)** ทั้งก่อนหรือหลัง peer review
- **ไม่ได้ออกแบบสำหรับ:** เรียงความสั้น รายงานทั่วไป หรือเอกสารที่ไม่ใช่วิชาการ
- รายงานจะเขียนตามภาษาหลักของเอกสาร (เอกสารภาษาไทย → รายงานภาษาไทย/สองภาษา)
- ระดับความร้ายแรงใช้ป้ายข้อความ `[Critical]` `[Major]` `[Minor]` `[Strength]`
  (เอกสารทางการจึงไม่ใช้อีโมจิหรือสัญลักษณ์ตกแต่ง)

## ข้อควรระวัง

- การรีวิวโดย AI เป็นเครื่องมือช่วยตรวจเบื้องต้น ไม่แทนการตัดสินของอาจารย์ที่ปรึกษา
  หรือคณะกรรมการสอบที่แท้จริง ผู้เขียนควรใช้วิจารณญาณตรวจสอบข้อเสนอแนะก่อนนำไปแก้ไข
- ไฟล์วิทยานิพนธ์เป็นเอกสารส่วนบุคคล ผู้ใช้ควรพิจารณานโยบายความเป็นส่วนตัวของเครื่องมือ AI
  ที่ใช้ก่อนส่งไฟล์เข้าตรวจ
